# staging: one model per source table

Staging renames, casts, unnests and deduplicates. There are no joins and no business rules here; those start in
`intermediate`. Every model is a view in schema `staging`.

## The pattern

All models follow the same four steps. `stg_ym__orders.sql` is the shortest example.

1. `src` reads `{{ source_or_seed('<table>') }}`. That is the RAW table, or `ref('demo_<table>')` when
   `var('use_demo_seeds')` is on (`macros/source_or_seed.sql`).
2. `latest` keeps the latest load per natural key. RAW is append-only and the same period can be exported twice
   (`qualify row_number() over (… order by _loaded_at desc) = 1`).
3. `renamed` gives snake_case names and explicit casts (`try_to_*` for marketplace-formatted strings) and reads JSON
   with `parse_json`.
4. A nested array inside a RAW row gets its own model at its own grain. For orders_stats that means
   `stg_ym__orders` (order), `_order_lines` (items), `_order_line_events` (items[].details), `_order_fees`
   (commissions) and `_order_payments` (payments).

## Sources

| source | tables | how the docs are written |
|---|---|---|
| `yandex_market` | orders_stats, business_orders, offer_mappings, goods_realization (5 appendices, unioned in `stg_ym__realization_lines`), stock_reports, warehouses, goods_turnover, united_orders | `_ym__sources.yml` is generated by `scripts/gen_sources_yml.py` from the downloaded files and the seller-API spec. It describes every raw column, and `--check` fails if one is undocumented. `ingest/load_to_snowflake.py` writes the same text into Snowflake comments |
| `finance` | cogs_by_sku: unit cost per SKU × cost version, compiled from the partner's workbooks | `_finance__sources.yml`, written by hand (one table with a fixed layout) |

The marketplace's formats stop at staging. This is where `'Нет продаж'` in a numeric column gets handled, dates get
cut out of a file path and prices get split into buyer, marketplace and cashback parts. Values stay as the
marketplace prints them, Russian labels included. Names and types follow the project's conventions.

## Tests

Keys get `unique` + `not_null` at the model's grain. Status and type columns that downstream logic branches on get
`accepted_values`, so a new value fails the build instead of falling into an `else`. Source freshness is
configured on the RAW tables.

`stg_ym__stock_levels` reads the stock report. It replaced the JSON stocks endpoint on 2026-09-14 because the report
has history (`reportDate`) and the endpoint only returned today.
